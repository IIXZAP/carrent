# carrent — version 2 (เขียนใหม่ตั้งแต่ศูนย์) · PHP MVC + PDO + MySQL + Tailwind

เวอร์ชัน basic ของระบบเช่ารถ ใช้ schema ใหม่ (`database/migrations/001_schema.sql`)

> branch นี้ (`rewrite/v2`) มีเฉพาะโปรเจกต์ใหม่ที่ root — ระบบเดิมอยู่ใน branch `main`
> เอกสารของระบบเดิม (CODE_MAP, reference ทีละเมธอด, README เก่า) เก็บไว้ที่ `docs/legacy/` ใช้เป็นสเปกกฎธุรกิจตอน port
รันบน shared hosting ได้ (ไม่ต้องมี Composer/Node บนเซิร์ฟเวอร์ — `assets/css/app.css` build แล้ว commit ไว้)

## รันบนเครื่อง

```bash
# 1) สร้างฐานข้อมูล แล้วตั้งค่าเชื่อมต่อ (config/config.local.php หรือ env DB_HOST/DB_NAME/DB_USER/DB_PASS)
mysql -uroot -e "CREATE DATABASE carrent_v3 CHARACTER SET utf8mb4"

# 2) สร้างตาราง (รันซ้ำได้ ข้ามไฟล์ที่เคยรันแล้ว)
php bin/migrate.php

# 3) สร้างผู้ใช้หลังบ้าน (จะถามรหัสผ่าน อย่างน้อย 10 ตัว)
php bin/create-admin.php owner@example.com "เจ้าของร้าน" admin

# 4) เปิดเซิร์ฟเวอร์
php -S localhost:8000 index.php
```

หน้าลูกค้า `/` · หลังบ้าน `/admin`

แก้หน้าตา: `npm install && npm run build` (ต้นฉบับ `assets/css/src/input.css`)

## โครงสร้าง

```
index.php            front controller
app/bootstrap.php    autoload (App\), config, timezone, session, error handler
app/routes.php       ตาราง URL → [Controller, method] (+ middleware 'auth' / 'admin')
app/Core/            Router, Database (PDO), View, Session, Csrf, Flash
app/Models/          SQL ทั้งหมดอยู่ที่นี่ (Car, CarType, User)
app/Services/        กฎธุรกิจ (Auth, CarService)
app/Controllers/     บาง: รับค่า → เรียก Service/Model → ส่ง View
app/Views/           เทมเพลต PHP + Tailwind
database/migrations/ ไฟล์ .sql เรียงตามชื่อ ห้ามแก้ไฟล์ที่รันแล้ว — เพิ่มไฟล์ใหม่แทน
bin/                 migrate.php, create-admin.php
```

กฎ: SQL อยู่ใน Model เท่านั้น · View ครอบข้อมูลผู้ใช้ด้วย `e()` ทุกจุด · POST ทุกเส้นตรวจ CSRF โดย Router

ไฟล์ migration: ห้ามมี `;` หรือ `--` อยู่ในข้อความ string (ตัวรันแยกคำสั่งแบบง่าย)

## ทำเสร็จแล้ว

**slice 0–1**
- โครงแกน, migration runner, ล็อกอิน/ออกจากระบบ (role admin/staff)
- จัดการรถหลังบ้าน (เพิ่ม/แก้/ลบแบบ soft delete — ลบไม่ได้ถ้ามีการจองค้างอยู่)
- หน้าลูกค้า: รายการรถ + รายละเอียดรถ

**slice 2: ตรวจรถว่าง + คิดราคา**
- `PricingService` (ฟังก์ชันล้วน ไม่แตะ DB): นับวัน (ผ่อนผัน 2 ชม.), เหมาเดือน/สัปดาห์/วันที่ถูกที่สุด,
  บริการเสริม, ค่าส่งตามระยะทาง (`DeliveryFeeService`), VAT, มัดจำ, เงินประกัน
  — ยอดเงินปัดสตางค์ทุกขั้น และส่วนลดไม่เกินยอด เพื่อให้ผ่าน CHECK `subtotal`/`grand_total` ของตาราง `bookings`
- `AvailabilityService`: ตรวจรถว่าง (เว้นช่วงพักรถ `booking_gap_hours`, บล็อกวัน, รถที่เลยกำหนดคืนแต่ยังไม่รับคืนถือว่าไม่ว่าง),
  ตรวจเวลาทำการ/จองล่วงหน้า/ขั้นต่ำ/สูงสุด
- หน้าลูกค้า: หน้าแรกค้นหารถว่างตามวัน–เวลาพร้อมราคา, หน้ารถมีกล่องคำนวณราคา + บริการเสริม
- ค่าตั้งต้น: `database/migrations/002_seed_defaults.sql` (แก้ภายหลังที่ตาราง `settings` / `addons`)

**slice 3: สร้างการจอง**
- `BookingService::createBooking` — ที่เดียวที่สร้างการจอง (เว็บและหลังบ้านเรียกผ่านที่นี่)
  ทำใน transaction เดียว: **ล็อกแถวรถเป็นคำสั่งแรก** → ตรวจรถว่าง → คิดราคา → หา/สร้างลูกค้า (ตามเบอร์โทร) → ขอเลขที่จอง → บันทึก
  ถ้าไม่ว่าง/ผิดพลาด rollback หมด (ไม่มีลูกค้าหรือเลขที่จองค้าง)
- เว็บ: หน้ารถ → `/booking` (ฟอร์ม + สรุปราคา) → `/booking/success/{เลขที่จอง}` (เปิดได้เฉพาะเจ้าของ session เพราะเลขที่จองเดาได้)
  กฎกันจองรัว: ค้างมัดจำ ≤ 3 ใบ/เบอร์, ≤ 8 ใบ/ชั่วโมง/IP, ลูกค้า blacklist จองออนไลน์ไม่ได้
- หลังบ้าน: `/admin/bookings` (กรองสถานะ/ค้นหา), รายละเอียด, สร้างการจอง (โทร/LINE/หน้าร้าน — กรอกส่วนลด/VAT/มัดจำเองได้), ยกเลิก (atomic)
- เบอร์โทรเก็บเป็นตัวเลขล้วน (`Phone::normalize`: `+66 81 234 5678` = `081-234-5678` = `0812345678`)
- `Database::begin()` ซ้อนได้ (ชั้นในใช้ SAVEPOINT) เพื่อให้เทสต์ครอบด้วย transaction แล้ว rollback ได้
- `Database::retryOnDeadlock()` ลองใหม่จำกัดรอบเมื่อเป็นเหยื่อ deadlock (1213) — ใช้ครอบการสร้างการจอง ข้อผิดพลาดอื่นไม่ลองซ้ำ

**slice 4: ชำระเงิน / สลิป**
- ลูกค้า: `/track` ค้นการจองด้วยเลขที่จอง + เบอร์โทร (ผิดเกิน 20 ครั้ง/15 นาที/IP จะถูกระงับ) → ดูสถานะ/ยอดคงเหลือ → แจ้งโอน (แนบสลิป)
  หลังจองสำเร็จเข้าหน้าแจ้งโอนได้ทันที ไม่ต้องกรอกเลขที่จองอีก
- แอดมิน: `/admin/payments` ตรวจสลิป (อนุมัติ/ปฏิเสธ + เหตุผลที่ลูกค้าเห็น), หน้ารายละเอียดการจองมีส่วนการชำระเงิน
  (บันทึกรับเงินสด/โอน, รับเงินประกัน, คืนค่าเช่า, คืนเงินประกัน, หักเงินประกันชำระยอดค้าง — อนุมัติทันที)
- `/admin/settings` (เฉพาะเจ้าของร้าน): เบอร์ร้าน/บัญชีรับโอน, เวลาทำการ, กติกาการจอง, มัดจำ/เงินประกัน/VAT, ค่าส่งรถ
- มัดจำครบ (จากรายการค่าเช่า) → การจองเปลี่ยนเป็น "ยืนยันแล้ว" อัตโนมัติ ; ยอดที่ชำระแล้วไม่เก็บซ้ำใน `bookings` คำนวณจาก `payments` เสมอ (`Payment::netPaid`)
- เงินประกันไม่ใช่รายได้ (`Payment::REVENUE_SQL`) ; migration 006 เพิ่ม kind `security_refund` และ method `deduct` + ปรับ VIEW `v_booking_payment` (เทสต์เทียบกับสูตรในโค้ด)
- **สลิปเก็บใน `storage/private/slips/`** (เปิดผ่านเว็บตรงๆ ไม่ได้) ชื่อไฟล์เป็นเลขสุ่ม ตรวจชนิดจากเนื้อไฟล์ (JPG/PNG/WEBP ≤ 8 MB)
  ดูได้เฉพาะแอดมินที่ล็อกอิน หรือเจ้าของการจอง (ยืนยันด้วยเลขที่จอง + เบอร์) — **ตั้ง `upload_max_filesize` / `post_max_size` ของ PHP ให้ ≥ 8M** (ค่าตั้งต้นของหลายโฮสต์คือ 2M)
- **ยกเลิกการจองที่ไม่จ่ายมัดจำอัตโนมัติ:** ตั้งเวลาที่ ตั้งค่าร้าน → `pending_expire_hours` (ค่าตั้งต้น 24 ชม., 0 = ปิด) และ **ต้องตั้ง cron เรียก `php bin/cron.php` ทุกชั่วโมง**
  (cPanel → Cron Jobs: `0 * * * * /usr/bin/php /home/USER/public_html/bin/cron.php`) ไม่งั้นไม่มีผล
  ยกเลิกเฉพาะการจองหน้าเว็บ/ยังรอยืนยัน/ไม่มีเงินเข้า/ไม่มีสลิปรอตรวจ — การจองที่พนักงานสร้างไม่ถูกยกเลิกเอง · ลูกค้าเห็นกำหนดชำระในหน้าจองสำเร็จและหน้าตรวจสอบการจอง
- **ค่าส่งรถ:** เลือกส่ง/รับรถถึงที่ต้องกรอกระยะทาง (กม.) — ระยะที่ลูกค้ากรอกไม่ได้ถูกตรวจสอบ จึงแสดงในหน้าแอดมิน
  และพนักงาน **ปรับค่าส่งได้ก่อนรับรถ** (ระบุค่าส่งต่อเที่ยวเอง หรือระยะจริงให้คิดตามตาราง + เหตุผลบังคับ) ยอดรวม/VAT/สถานะชำระเงินคำนวณใหม่ และบันทึก log
- **จำกัดการเดารหัสผ่านหลังบ้าน:** ผิดเกิน 10 ครั้ง/IP หรือ 30 ครั้ง/อีเมล ใน 15 นาที ถูกระงับ (รหัสถูกก็เข้าไม่ได้ช่วงนั้น)
- ทุกเส้นทางที่แก้ยอดเงินล็อกแถวการจองก่อน (`Booking::lockForUpdate`) และเปลี่ยนสถานะสลิปด้วย `UPDATE ... WHERE status='pending'`

**ตั้งค่าเมื่อเว็บอยู่หลัง proxy/CDN:** ตั้ง env `TRUST_PROXY=1` (ไม่งั้นทุกคนมี IP เดียวกัน แล้วขีดจำกัด 8 ใบ/ชั่วโมง/IP จะบล็อกลูกค้าทั้งร้าน)
ห้ามเปิดถ้าเข้าเซิร์ฟเวอร์ตรงๆ เพราะผู้ใช้จะปลอม IP ได้

**slice 5: ส่งมอบ–รับคืนรถ**
- ขั้นตอนในหน้ารายละเอียดการจอง (`ขั้นตอนงาน`): ยืนยัน → ส่งมอบ → รับคืน → ปิดงาน → ปิดเงินประกัน ทุกขั้นเปลี่ยนสถานะด้วย `UPDATE ... WHERE status IN (...)`
  ใน transaction ที่ล็อก **รถ → การจอง** (กดซ้ำ/สองแท็บ/สองคนพร้อมกัน ผ่านได้ครั้งเดียว กดย้อนหรือข้ามขั้นไม่ได้)
- **ส่งมอบ:** เลขไมล์ + ขีดน้ำมัน → ล็อกผลตรวจรอบส่งมอบ (สภาพรถวันส่งมอบต้องนิ่ง) · ส่งมอบไม่ได้ถ้ารถคันนี้ยังอยู่กับลูกค้ารายอื่น
  เตือน (ไม่บล็อก) ถ้ามัดจำ/เงินประกันยังไม่ครบ หรือถ่ายรูปไม่ครบ
- **รับคืน 2 ขั้น:** กรอกไมล์/น้ำมัน/เวลาคืน → ระบบคำนวณค่าใช้จ่ายที่แนะนำ (คืนช้า, น้ำมันขาด, ระยะทางเกิน — port จากระบบเดิม ตรวจด้วย golden 389 เคส)
  → พนักงานยกเว้น/แก้ยอด/เพิ่มค่าใช้จ่ายอื่น → ยืนยัน (เก็บทั้งยอดแนะนำและยอดจริง) · ยอดที่ต้องชำระและสถานะชำระเงินคิดใหม่ · ลูกค้าเห็นรายการค่าใช้จ่ายเพิ่ม
- **ปิดเงินประกัน:** หักชำระยอดค้าง (+ ค่าใช้จ่ายที่พบหลังรับคืน) แล้วคืนส่วนที่เหลือ — ทำได้ครั้งเดียว (กดซ้ำ/พร้อมกันคืนเงินซ้ำไม่ได้)
- **ตรวจสภาพรถ:** ถ่ายรูป 8 มุม ทั้งรอบส่งมอบและรับคืน — ถ่ายแทนได้แต่รูปเดิมเก็บเป็นประวัติ (ไม่ลบ) · จุดมีตำหนิถ่ายได้หลายรูป · ล็อกเมื่อจบรอบ
  (ด่านสุดท้ายอยู่ที่ Model) · รูปเก็บใน `storage/private/inspections/` ดูผ่านหลังบ้านเท่านั้น
- ตั้งค่าร้าน: ค่าปรับคืนช้า/น้ำมัน/ระยะทางเกิน (migration 008 + หน้าตั้งค่า) · `bookings.extra_breakdown` เก็บรายละเอียดค่าใช้จ่ายเพิ่ม

**slice 6: เอกสารและลายเซ็น**
- **เอกสาร** (เมนู "เอกสาร"): ใบเสนอราคา · ใบแจ้งหนี้ · ใบเสร็จ · สัญญา — สร้างเปล่า หรือกด "+ ใบ..." จากหน้าการจองเพื่อเติมรายการจากการจอง
  (ค่าเช่า + บริการเสริมตามตารางจริง − ส่วนลด + VAT ตรงกับยอดการจองทุกบาท ; ใบแจ้งหนี้/ใบเสร็จเพิ่มค่าใช้จ่ายหลังรับคืนด้วย)
- ยอดคิดที่ `DocumentService::totals` ปัดเศษทุกขั้น: ราคา/หน่วยปัดเท่าที่ DB เก็บ → ยอดบรรทัด → รวม → ลบส่วนลด → VAT → หัก ณ ที่จ่าย (ตัวเลขบนกระดาษบวกกลับได้พอดี)
- เลขที่ `QT/IV/RC/CT` + `yymm-0000` ออกจากตัวนับแบบ atomic (พร้อมกัน 8 process ได้เลขไม่ซ้ำไม่ขาด) · สถานะ ร่าง → ส่งแล้ว → ยอมรับ → ชำระแล้ว/ยกเลิก
  **ชำระแล้วและยกเลิกแล้วแก้ไม่ได้ ย้อนสถานะไม่ได้** · พิมพ์ A4 / บันทึกเป็น PDF จากเบราว์เซอร์
- **ลายเซ็นลูกค้า:** หน้า "สัญญา / ลายเซ็น" ในการจองออกลิงก์ลับ (รหัส 128 บิต, สร้างครั้งแรกที่เปิดหน้านี้ แล้วใช้รหัสเดิมตลอด) ส่งให้ลูกค้าเปิดบนมือถือ ไม่ต้องล็อกอิน
  ชนิด `สัญญาเช่า` (เซ็นได้ก่อนส่งมอบ) และ `ใบรับคืนรถ` (หลังรับคืน) — ลิงก์ผิด/รหัสไม่ตรงตอบ 404 เหมือนกันหมด · ตอบ `no-store`, `noindex`, `no-referrer`
- **หลักฐาน:** ตอนเซ็นเก็บสำเนา (ข้อมูลสำคัญ + ข้อความสัญญา + ข้อความ PDPA + รายชื่อรูปตรวจสภาพ) พร้อม SHA-256, เวลา, IP, อุปกรณ์ ·
  หน้าเซ็นฝัง hash ของ "สิ่งที่ลูกค้าเห็น" แล้วเทียบอีกครั้งตอนกดยืนยัน **ในการล็อกการจอง** — ร้านแก้ข้อมูลระหว่างนั้นต้องให้ลูกค้าตรวจใหม่ ·
  แก้ข้อมูลหลังเซ็น หน้าหลังบ้านและใบพิมพ์เตือนว่าอะไรต่างจากที่เซ็น · แก้สำเนาในฐานข้อมูลโดยตรงถูกจับได้ด้วย hash
- รูปลายเซ็นถูก "วาดใหม่" ด้วย GD บนพื้นขาว (ข้อมูลแฝงในไฟล์หลุดหมด) ตรวจเป็น PNG จริง ขนาด 120–2400×60–1600 และมีหมึกจริง ·
  เซ็นซ้ำ/พร้อมกันได้ฉบับเดียว (ไฟล์ของฉบับที่แพ้ถูกลบ) · **ลายเซ็นไม่ถูกลบ**: ขอเซ็นใหม่ = เจ้าของร้านยกเลิกฉบับเดิมพร้อมเหตุผล (เก็บประวัติและไฟล์) · ไฟล์อยู่ `storage/private/signatures/`
- ตั้งค่าร้าน: ชื่อ/ที่อยู่/เลขผู้เสียภาษีของร้าน (ขึ้นบนเอกสาร), ข้อความ PDPA, ข้อสัญญาเพิ่มเติม (migration 009) — **ข้อสัญญามาตรฐานใน `app/Views/partials/contract_terms.php` ต้องให้ทนายของร้านตรวจก่อนใช้จริง**
- ตั้ง `APP_URL` (เช่น `https://rent.example.com`) เพื่อให้ลิงก์ที่ส่งลูกค้าใช้โดเมนจริง (ไม่ตั้งจะอนุมานจากคำขอ)

**แจ้งเตือนร้านทาง LINE (ขั้น 7)** — หลังบ้าน → "แจ้งเตือน LINE" (เฉพาะเจ้าของร้าน, migration 011)
- แจ้งเข้า LINE ของร้านเมื่อ: **มีจองใหม่จากหน้าเว็บ · ลูกค้าแจ้งโอน (สลิปใหม่) · ลูกค้าเซ็นสัญญา/ใบรับคืน** — เปิด/ปิดแยกเหตุการณ์ได้ ข้อความมีลิงก์เปิดงานในหลังบ้าน
- **วิธีตั้งค่า:** สร้าง LINE Official Account + เปิด Messaging API ที่ LINE Developers Console → ออก "Channel access token (long-lived)" → วางในหน้านี้ พร้อมรหัสผู้รับ (User ID ของเจ้าของ/พนักงาน อยู่ที่ Channel → Basic settings → "Your user ID" ขึ้นต้น `U`; ผู้รับต้องเพิ่ม OA เป็นเพื่อนก่อน) → กด "ส่งข้อความทดสอบ"
- ผู้รับได้สูงสุด 10 รหัส (`U` ผู้ใช้ / `C` กลุ่ม / `R` ห้อง) · token เก็บในตาราง `settings` (ไม่แสดงซ้ำหลังบันทึก เห็นแค่ 4 ตัวท้าย) — ใครเข้าฐานข้อมูลได้ก็อ่านได้ ถ้าหลุดให้ Reissue ที่ LINE
- **ข้อความมีชื่อและเบอร์โทรลูกค้า** (PDPA) — ใส่เฉพาะคนที่ควรเห็นข้อมูลนี้
- **ออกแบบให้ LINE ล่มแล้วไม่กระทบงานหลัก:** เข้าคิว (`notifications`) ก่อนแล้วส่งหลังตอบหน้าเว็บ (ลูกค้าไม่รอ LINE) · ส่งไม่ผ่านจะลองใหม่ 1 นาที → 5 นาที → 30 นาที → 2 ชม. (รวม 5 ครั้ง) แล้วค้างเป็น "ไม่สำเร็จ" ให้กด "ส่งใหม่" ในหลังบ้าน ·
  token ผิด/รหัสผู้รับผิดจะไม่ลองซ้ำ (บอกสาเหตุในตาราง) · ส่งซ้ำไม่เบิ้ล: หลาย process ส่งพร้อมกันได้ข้อความละครั้ง (claim แบบ atomic), เหตุการณ์เดียวกันแจ้งครั้งเดียว (`dedupe_key`), และส่ง `X-Line-Retry-Key` ให้ LINE
- **ต้องตั้ง cron** (`php bin/cron.php` ทุกชั่วโมง) เพื่อส่งรายการที่พลาดซ้ำ, คืนแถวที่ค้างระหว่างส่ง, และลบประวัติ (ส่งแล้ว >60 วัน / ไม่สำเร็จ >180 วัน)
- ปลายทาง API ตั้งได้เฉพาะทาง `LINE_API_BASE`/`config.local.php` (ใช้ในเทสต์) ไม่มีช่องให้แก้ในหลังบ้าน

## หมายเหตุ

- แจ้งเตือน LINE ทำเฉพาะ "แจ้งร้าน" — ยังไม่มีแจ้งลูกค้าทาง LINE (ต้องมี webhook/LIFF ผูกบัญชีลูกค้า) และยังไม่มีแจ้งอีเมล
- ลายเซ็นอิเล็กทรอนิกส์นี้เป็นหลักฐานประกอบ (ใครเซ็น เมื่อไร ข้อมูลอะไร) ไม่ใช่ลายเซ็นดิจิทัลที่ออกโดยผู้ให้บริการรับรอง — เรื่องน้ำหนักทางกฎหมายให้ปรึกษาทนายของร้าน
- ฟิลด์ที่ลูกค้าเซ็นรับรองยังไม่รวมเอกสารบัตร/ใบขับขี่ (ยังไม่ได้ทำการอัปโหลดเอกสารลูกค้า) — ตอนนี้ดูได้จากตัวเลขสลิปรอตรวจที่เมนู "ชำระเงิน" และหน้าภาพรวม
- รูปที่อัปโหลดถูกย่อในเบราว์เซอร์ก่อนส่ง (ฝั่งเซิร์ฟเวอร์ยังเก็บไฟล์ตามที่รับมา)
- เบอร์โทรของลูกค้าที่ยังใช้งานอยู่ต้องไม่ซ้ำ (UNIQUE `phone_active`, migration 005) — จองพร้อมกันด้วยเบอร์ใหม่เดียวกันจึงได้ลูกค้าแถวเดียว
  ถ้าย้ายข้อมูลลูกค้าจากระบบเดิมมา ต้องรวมแถวที่เบอร์ซ้ำก่อนรัน migration นี้ (วิธีตรวจอยู่ในหัวไฟล์)
- ค่าส่งรถคิดตามระยะทาง (`settings.delivery_tiers`) จึงไม่ได้ใช้คอลัมน์ `cars.delivery_fee` — พิจารณาตัดคอลัมน์นี้ใน migration ถัดไป
